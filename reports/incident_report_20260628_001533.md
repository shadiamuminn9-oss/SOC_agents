# Incident Report 2026-06-28

## Executive Summary
A series of brute-force attacks were detected, culminating in a successful root login from a known malicious IP address. Subsequent investigation revealed outbound command and control (C2) communication to a reported C2 infrastructure, indicating a potential compromise. Immediate action is required to contain the threat and prevent further unauthorized access.

## Findings

| Indicator        | Activity                                                                                             | Severity | MITRE Technique                                     |
| :--------------- | :--------------------------------------------------------------------------------------------------- | :------- | :-------------------------------------------------- |
| 185.220.101.47   | Multiple failed login attempts for various users (root, admin, ubuntu)                               | High     | T1110 - Brute Force                                 |
| 185.220.101.47   | Successful root login after multiple failed attempts                                                 | Critical | T1078 - Valid Accounts (Initial Access via T1110)   |
| 45.155.205.233   | Multiple failed login attempts for invalid users (oracle, postgres, test)                            | Medium   | T1110 - Brute Force                                 |
| 198.51.100.22    | Multiple failed login attempts for root                                                              | Medium   | T1110 - Brute Force                                 |
| 185.220.101.47   | Port scan activity targeting multiple common ports (22, 23, 80, 443, 3306, 8080, 5432)               | High     | T1595 - Active Scanning                             |
| 94.102.61.7      | Outbound connection to a suspicious port (4444), potentially C2 or reverse shell                     | Critical | T1071 - Application Layer Protocol (C2)             |
| 45.155.205.233   | Port scan activity specifically targeting SSH port 22                                                | Medium   | T1595 - Active Scanning                             |

## Recommended Remediation

1.  Immediately block IP addresses `185.220.101.47`, `45.155.205.233`, `198.51.100.22`, and `94.102.61.7` at the perimeter firewall.
2.  Force a password reset for the `root` account and all other administrative accounts. Implement a strong password policy requiring minimum length, complexity, and regular rotation.
3.  Enable multi-factor authentication (MFA) for all administrative accounts, especially `root`, and critical user accounts.
4.  Implement account lockout policies for failed login attempts (e.g., lock account after 5 failed attempts for 30 minutes).
5.  Review system logs for any unauthorized activity post-root login from `185.220.101.47` to identify persistence mechanisms, data exfiltration, or further compromise.
6.  Restrict direct SSH access for the `root` user. Instead, use a non-privileged user and `sudo` for administrative tasks.
7.  Harden SSH configurations by disabling password authentication and enforcing key-based authentication.
8.  Implement egress filtering on firewalls to prevent outbound connections to known malicious IP addresses and suspicious ports like 4444.
9.  Conduct a comprehensive vulnerability scan of all internet-facing systems to identify and remediate exposed services and misconfigurations.
